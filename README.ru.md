# deep-search-stack

*[English version](README.md)*

Self-hosted веб-ресёрч для Claude Code и скилл, который им управляет. Один
запрос уходит сразу в два независимых стека и возвращается одним сводным
отчётом.

| Ветка | Чем ищет | Стоимость |
|---|---|---|
| `tavily+jina` | поиск Tavily, текст страниц через Jina Reader | платные API-ключи |
| `searxng+crawl4ai` | self-hosted SearXNG, текст страниц через Crawl4AI | бесплатно, локально |

Результаты сливаются по URL. Страница, найденная обеими ветками, идёт первой и
помечена двумя источниками — ради этой перекрёстной проверки две ветки и
существуют.

```
Claude Code
   │
   ├── скилл deep-search ──┬──> custom-search/search.py ──> Tavily + Jina
   │                       │
   │                       └──> импорт модулей mcp-server ──┬──> searxng :8880
   │                                                        └──> crawl4ai :11235
   │
   └── MCP searxng-crawl :8765 ─────────────────────────────┘
       (те же сервисы, маршрут через tool call)
```

Два маршрута к одним и тем же сервисам — так и задумано. Скилл не тратит
контекст, пока его не вызвали: схемы инструментов не загружаются. MCP-сервер
нужен, когда хочется `search_and_scrape` или `social_search` обычным tool call.

## Структура

| Путь | Что внутри |
|---|---|
| `docker-compose.yml` | три сервиса: SearXNG, Crawl4AI, MCP-сервер |
| `mcp-server/` | MCP-сервер — см. [Инструменты MCP](#инструменты-mcp) |
| `tests/` | тесты MCP-сервера, `httpx.MockTransport`, без сети |
| `searxng/settings.yml.example` | шаблон конфига SearXNG |
| `skills/deep-search/` | скилл: `SKILL.md`, `scripts/deep_search.py`, `tests/e2e.sh` |
| `skills/custom-search/` | ветка `tavily+jina`, запускается скиллом как подпроцесс |
| `scripts/install-skills.sh` | линкует оба скилла в `~/.claude/skills` |

## Установка

```bash
cp .env.example .env          # заполнить CRAWL4AI_API_TOKEN: openssl rand -hex 32
cp searxng/settings.yml.example searxng/settings.yml
                              # заменить ultrasecretkey: openssl rand -hex 32
docker compose up -d --build
```

`.env` и настоящий `settings.yml` в `.gitignore` — в них секреты.

Поставить скиллы и указать им путь к этому чекауту:

```bash
./scripts/install-skills.sh
export INTERNET_CLAUDE_DIR="$PWD"     # добавить в ~/.zshrc или ~/.bashrc
```

По желанию — зарегистрировать MCP-сервер:

```bash
claude mcp add --transport http --scope user searxng-crawl http://127.0.0.1:8765/mcp
```

## Запуск скилла

```bash
# 50 источников с каждой ветки, 10 прочитаны целиком
~/.claude/skills/deep-search/scripts/deep_search.py "Crawl4AI vs Firecrawl"

# быстро, одной веткой
~/.claude/skills/deep-search/scripts/deep_search.py "python 3.14 release" \
    --only searxng --max-results 5 --full-pages 3

# ресёрч плюс то, что пишут в соцсетях
~/.claude/skills/deep-search/scripts/deep_search.py "Claude Code hooks" --social
```

Полная таблица флагов, формат вывода, расшифровка отказов и поведение прокси —
в [`skills/deep-search/SKILL.md`](skills/deep-search/SKILL.md).

Вывод двухъярусный: сначала страницы, прочитанные целиком, затем
`## Ещё источники` — остальные по одной строке с заголовком, URL, движком и
сниппетом, чтобы дочитать нужную адресно. Обе ветки упали — exit code `3` и
причины в stderr; упала одна — это сказано в шапке, вторая продолжает отвечать.

## Как вызывать из Claude Code

Три входа, скрипт под ними один:

| Как | Что происходит |
|---|---|
| `/deep-search python 3.14 release notes` | явный вызов, запрос — всё, что после команды |
| обычная просьба: «найди, что пишут про X» | описание скилла совпадает, Claude запускает его сам |
| строка `bash` выше | без Claude вообще, отчёт уходит в stdout |

`/custom-search` — ручной маршрут по одному источнику: только Tavily и Jina,
без SearXNG. Он намеренно отключён для автовызова, чтобы Claude не выбирал его
вместо `deep-search`.

Флаги можно называть словами, скилл сам их разложит: «быстро глянь» →
`--only tavily --max-results 5 --full-pages 3`, «перерой всё» →
`--max-results 80 --full-pages 20`, «только за неделю» → `--time-range week`,
«что в соцсетях» → `--social`.

## Язык ответа

Две независимые настройки: что ищем и на чём отвечаем.

**Что ищем** — флаг `--language`, он уходит в SearXNG:

```bash
# только русскоязычный веб
~/.claude/skills/deep-search/scripts/deep_search.py "тарифы на электричество" --language ru

# только англоязычный веб
~/.claude/skills/deep-search/scripts/deep_search.py "electricity tariffs" --language en
```

По умолчанию `all` — оба вперемешку. Сужать имеет смысл, когда ответ зависит от
региональных источников: цены, законы, местные сервисы.

**На чём отвечаем** — решается в самом запросе, флага для этого нет. Claude
отвечает на языке вопроса; чтобы переключить, скажи это прямо:

```
/deep-search Crawl4AI vs Firecrawl — ответь по-русски
/deep-search тарифы на электричество в Москве --language ru, answer in English
```

Каркас отчёта, который печатает скрипт, — шапка, `## Ещё источники`,
`### Не удалось получить` — всегда на русском. Текст страниц приходит на языке
оригинала; при ответе Claude переводит нужное.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `CRAWL4AI_API_TOKEN` | обязательна: Crawl4AI требует её на каждом эндпоинте |
| `SEARXNG_PORT`, `CRAWL4AI_PORT`, `MCP_PORT` | порты на хосте, только на `127.0.0.1` |
| `INTERNET_CLAUDE_DIR` | путь к этому чекауту, по умолчанию `~/internet-claude` |
| `TAVILY_API_KEY_1..3`, `JINA_API_KEY` | ветка `tavily+jina` |
| `DEEP_SEARCH_PROXY` | прокси для внешних запросов, по умолчанию `http://127.0.0.1:8118`, пустое значение = напрямую |
| `DEEP_SEARCH_SEARXNG_URL`, `DEEP_SEARCH_CRAWL4AI_URL` | полные URL, если сервисы не на локальных портах по умолчанию |
| `SOCIAL_*`, `BLUESKY_*`, `YOUTUBE_API_KEY` | опциональные соц-источники, см. `.env.example` |

Прокси по умолчанию рассчитан на то, что на `127.0.0.1:8118` кто-то слушает
(Privoxy или аналог). Если там пусто, скилл говорит об этом в шапке и работает
напрямую; `--no-proxy` или `DEEP_SEARCH_PROXY=` выключают прокси совсем.

## Инструменты MCP

| Инструмент | Для чего |
|---|---|
| `search_and_scrape(query, …)` | Обычный случай: найти и вернуть читаемый текст верхних страниц. |
| `search(query, …)` | Только заголовки, URL и сниппеты. Дёшево выбрать, что стоит читать. |
| `fetch_url(url, …)` | Одна страница, URL которой уже известен. |
| `social_search(query, …)` | Что пишут в соцсетях — сразу по всем настроенным платформам. |
| `social_sources()` | Какие платформы доступны и чего не хватает остальным. |

`search_and_scrape` режет вывод дважды: `max_chars_per_page` (по умолчанию 4000)
и жёсткий потолок `MAX_TOTAL_CHARS` в `mcp-server/server.py`. Без них пять
необрезанных страниц спокойно кладут в контекст 150–200 тыс. символов.
Результаты дедуплицируются до двух страниц на хост, чтобы один многословный сайт
не съел весь бюджет.

## Поиск по соцсетям

`social_search` — единая точка входа над несколькими платформами. Он веером
опрашивает их параллельно, приводит любой ответ к одной форме поста, схлопывает
ссылки, встретившиеся больше чем на одной платформе, и ранжирует итог. Сырые
метрики несравнимы — очки HN идут на тысячи, лайки Mastodon на десятки, — поэтому
каждый пост ранжируется относительно постов *своего* источника, а полученный
перцентиль складывается со свежестью.

| Источник | Как читает | Что нужно |
|---|---|---|
| `hackernews` | индекс Algolia, настоящий поиск по ключевым словам | ничего |
| `mastodon` | публичные ленты хэштегов | ничего (инстансы настраиваются) |
| `web` | SearXNG, ограниченный соц-хостами | сервис SearXNG |
| `reddit` | архив Arctic Shift, листинг плюс локальный фильтр по словам | `SOCIAL_REDDIT_SUBREDDITS` |
| `telegram` | публичные превью `t.me/s/<канал>` | `SOCIAL_TELEGRAM_CHANNELS` |
| `rss` | RSS/Atom-ленты, включая ленты каналов YouTube | `SOCIAL_RSS_FEEDS` |
| `bluesky` | `searchPosts` в AT Protocol | хэндл и app password |
| `youtube` | Data API v3 | API-ключ |

Результаты держатся в памяти 15 минут на источник и запрос, поэтому повтор в
рамках сессии не стоит ни одного обращения.

Ненастроенный источник просто не участвует, а не считается сломанным; спроси его
по имени в `platforms` — он скажет, чего именно ему не хватает. А вот источник,
который *упал*, всегда назван в конце ответа и никогда не выбрасывается молча:
сбой, поданный как «ничего не найдено», — худший способ для поискового
инструмента ошибиться.

### Чего здесь нет и почему

- **У X/Twitter нет бесплатного чтения.** Бесплатный тариф закрылся в феврале
  2026-го, план Basic за $200/мес отменили 1 июня 2026-го; чтение теперь
  поштучное, около $0,005 за пост. Источник `web` подбирает то, что публичные
  движки успели проиндексировать с `x.com`, — этим бесплатное покрытие и
  исчерпывается.
- **Reddit закрыл самостоятельную выдачу доступа к API** в ноябре 2025-го: новые
  ключи выдаются вручную, анонимные `.json`-эндпоинты отвечают 403. Дыру
  закрывает архив Arctic Shift, но он жёстко лимитирует и отвечает HTTP 422 с
  `Timeout. Maybe slow down a bit` в теле. Поэтому сабреддиты обходятся по
  одному с паузой, а отказ показывается, а не прячется. Для поиска по словам по
  всему Reddit надёжнее источник `web`.
- **У Mastodon нет полнотекстового поиска между инстансами**, поэтому первое
  слово запроса используется как хэштег.
- **Telegram и Reddit по словам через эти бесплатные маршруты не ищутся вообще**:
  оба адаптера листают то, что настроено, и фильтруют локально.

## Безопасность

`mcp-server/sanitize.py` резолвит каждый URL и отклоняет частные, loopback,
link-local и зарезервированные адреса. Инструменты принимают URL, предложенные
моделью, — без этой проверки сервер проксировал бы запросы внутрь compose-сети,
на docker-хост и к эндпоинтам метаданных облака. Скилл импортирует тот же
модуль, а не повторяет HTTP-контракты, поэтому ветку B вычищает ровно тот же
код.

## Разработка

```bash
uv sync
uv run pytest -q                      # MCP-сервер, без сети

DEEP_SEARCH_SCRIPT="$PWD/skills/deep-search/scripts/deep_search.py" \
    bash skills/deep-search/tests/e2e.sh
```

E2E-сьют покрывает 18 сценариев: каждая ветка по отдельности и вместе,
дедупликация, соц-блок, обе деградации, exit code 3, бюджет вывода, JSON,
`--time-range`, re-exec в venv, SSRF-вето, прокси по умолчанию, фолбэк на мёртвом
прокси и `--no-proxy`. Подряд не гонять — серия запросов заставляет движки
SearXNG отдавать капчу.

Тесты используют `httpx.MockTransport` и в сеть не ходят. Контейнер ставит
зависимости из того же `pyproject.toml`, что и тесты, поэтому образ и локальный
прогон не расходятся.

## Заметки

- JSON API у SearXNG выключен по умолчанию: в `search.formats` должен быть
  `json`, а `server.limiter` — `false`, потому что JSON-клиенты не шлют
  браузерных заголовков.
- Точка входа SearXNG делает chown своему конфигу, поэтому compose монтирует
  каталог `./searxng`, а не отдельный файл.
- `crawl4ai` нужен `shm_size: 1g`: с дефолтными 64 МБ Chromium падает на тяжёлых
  страницах.
- Добавить соц-платформу — это один класс в `mcp-server/sources.py` с `name`,
  `unavailable` и `async search(spec)` плюс одна запись в `build_sources`. В
  агрегаторе и инструментах ничего не меняется.
