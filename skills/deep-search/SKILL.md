# Deep Search Skill

Один запрос уходит сразу в два независимых стека, результаты сливаются по URL:

| Ветка | Чем ходит | Стоимость |
|---|---|---|
| `tavily+jina` | `~/.claude/skills/custom-search/scripts/search.py` (Tavily search + Jina Reader) | платные ключи |
| `searxng+crawl4ai` | self-hosted SearXNG `127.0.0.1:8880` + Crawl4AI `127.0.0.1:11235` напрямую по HTTP | бесплатно, без rate limit |

MCP-сервер `searxng-crawl` не участвует — скилл импортирует модули стека
(`backends.py`, `sanitize.py`, `sources.py`, `aggregate.py`, `social.py`)
из `INTERNET_CLAUDE_DIR` и бьёт по сервисам сам. В контекст ничего не грузится,
пока скилл не вызван.

## Когда использовать

- нужны разные поисковые движки на один вопрос (перекрёстная проверка);
- факт спорный, источники противоречат друг другу;
- свежие новости, changelog, release notes, GitHub issues;
- «собери всё, что есть по X» — обзор, сравнение, рынок;
- нужен ещё и срез по соцсетям (`--social`).

## Когда не надо

- один быстрый факт → этот же скилл с `--only tavily --max-results 5 --full-pages 3`
  (скилл `custom-search` отключён для автовызова, его скрипт — ветка A здесь);
- известен точный URL → `fetch_url` или `curl`;
- вопрос про API/конфиг конкретной библиотеки → скилл `find-docs`;
- внутреннее устройство GitHub-репозитория → скилл `deepwiki`.

## Команда запуска

```bash
~/.claude/skills/deep-search/scripts/deep_search.py "запрос" [флаги]
```

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--max-results N` | 50 | всего источников в отчёте **с каждой** ветки: полные + ссылки |
| `--full-pages N` | 10 | сколько источников прочитать целиком; остальные идут ссылкой со сниппетом |
| `--engines` | `auto` | `auto` — все general-движки SearXNG (сейчас 52); `builtin` — только включённые по умолчанию (4 реально ищущих); либо список через запятую |
| `--search-timeout N` | 40 | таймаут запроса к SearXNG; широкому пулу нужно больше 15 с |
| `--max-chars-per-page N` | 4000 | обрезка текста одной страницы |
| `--snippet-chars N` | 200 | обрезка сниппета у ссылки во втором ярусе |
| `--total-budget N` | 60000 | общий бюджет символов вывода |
| `--language LANG` | `all` | язык поиска SearXNG; `ru` сужает выдачу до русскоязычной |
| `--time-range` | `` | `day` \| `week` \| `month` \| `year` |
| `--only tavily\|searxng` | обе | отключить одну ветку |
| `--fresh` | off | `cache_mode=bypass` у Crawl4AI |
| `--social` | off | добавить блок `social_search` по 8 платформам |
| `--social-limit N` | 20 | постов в соц-блоке |
| `--social-per-platform N` | 8 | сколько просить у каждой платформы |
| `--social-chars N` | 600 | обрезка текста одного поста |
| `--json` | off | сырой JSON вместо markdown |
| `--no-proxy` | off | не использовать прокси в этом запуске |

## Примеры

```bash
# обычный ресёрч: 50 источников с ветки, 10 прочитаны целиком
~/.claude/skills/deep-search/scripts/deep_search.py "Crawl4AI vs Firecrawl"

# свежие новости за неделю, без платных ключей
~/.claude/skills/deep-search/scripts/deep_search.py "python 3.14 release" \
  --only searxng --time-range week

# глубокий разбор: больше полных страниц и бюджета
~/.claude/skills/deep-search/scripts/deep_search.py "Oppo Find X9 Pro vs Samsung S25 Ultra" \
  --max-results 80 --full-pages 20 --total-budget 120000

# ресёрч + что пишут в соцсетях
~/.claude/skills/deep-search/scripts/deep_search.py "Claude Code hooks" --social --full-pages 5
```

## Вывод

Шапка: `Источники — tavily+jina: N, searxng+crawl4ai: M, совпадений: K, прочитано
полностью: F`, затем `движки: запрошено 52, с результатами 12, без ответа 20` и
строка `прокси:`.

Дальше два яруса:

1. **Полные страницы** (`--full-pages`, по умолчанию 10) — заголовок, URL, метки
   источников и движка, текст. Запись, найденная обеими ветками, идёт первой и
   помечена двумя источниками сразу — сигнал «подтверждено двумя движками».
   Текст берётся тот, что длиннее.
2. **`## Ещё источники (N)`** — остальные ссылки строкой: заголовок, URL, движок,
   сниппет от движка. Это карта того, что ещё есть, для адресного дочитывания.

Если страница из первого яруса не открылась (Cloudflare, пустой HTML), её место
занимает следующая по списку — один добор, чтобы ярус не пустел.

## Как выбирать флаги по формулировке запроса

| Что просят | Чем запускать |
|---|---|
| «найди», «что пишут», обычный ресёрч | без флагов — 50 источников, 10 полных |
| «быстро глянь», «в двух словах» | `--only tavily --max-results 5 --full-pages 3` |
| «перерой всё», «максимально полно» | `--max-results 80 --full-pages 20 --total-budget 120000` |
| «только свежее», «за неделю» | `--time-range week` |
| «что в соцсетях», «что пишут люди» | `--social` |
| «поищи в гугле/брейве» | `--engines google cse,brave` |
| «только рунет» | `--language ru` |
| нужен конкретный сайт | `--engines auto` + читать ярус ссылок, потом `fetch_url`/`curl` по нужному URL |

Не конструируй URL руками. Ссылки берутся из отчёта — угаданные `id` и слаги
GSMArena/DXOMARK уводят на чужое устройство.

## Если источник упал

Упавшая ветка называется в блоке `### Не удалось получить`, вторая продолжает
работать, exit code остаётся `0`. Пустой список никогда не печатается как
«ничего не найдено». Расшифровка:

| Сообщение | Что делать |
|---|---|
| `tavily+jina — ERROR: No TAVILY_API_KEY_1..3 variables found` | ключи не в окружении процесса; настроить вне чата |
| `searxng+crawl4ai — нет каталога …/mcp-server` | задать `INTERNET_CLAUDE_DIR` |
| `searxng+crawl4ai — httpx недоступен` | `uv sync` в каталоге стека |
| `searxng+crawl4ai — CRAWL4AI_API_TOKEN не задан` | добавить токен в окружение или в `<repo>/.env` |
| `searxng+crawl4ai — SearXNG вернул 0 результатов; движки: …` | при `--engines auto` это редкость: пул из 52 движков переживает капчу на четырёх основных. Если всё же ноль — подождать или `--engines builtin` |
| `N ссыл(ок) от мусорных движков — домен не резолвится` | норма для широкого пула: часть движков отдаёт линкофермы, они отбрасываются до краула |
| `Blocked by anti-bot protection: Cloudflare JS challenge` | сайт закрыт от краулера; текст обычно приносит ветка `tavily+jina` — Jina тянет страницу со своей стороны |
| `прокси: … недоступен, работаю напрямую` | прокси-контейнер лежит; поднять его или смириться — mastodon и reddit будут в отказах |
| `ConnectError` на 8880/11235 | `docker compose up -d` в каталоге стека |

Обе ветки упали → exit code `3`, причины в stderr.

## Прокси

Внешние запросы по умолчанию идут через `http://127.0.0.1:8118`, localhost — никогда.
Скилл переписывает proxy-переменные своего процесса (`HTTP_PROXY`, `HTTPS_PROXY`,
`NO_PROXY=127.0.0.1,localhost`), поэтому один и тот же прокси получают и ветка B на
httpx, и subprocess ветки A на urllib. Собственный `NO_PROXY` машины при этом
затирается: httpx падает на IPv6-записях вида `::1` (`Invalid port: ':'`).

Перед запуском делается TCP-проба прокси. Мёртвый прокси не уносит все внешние
источники — работа продолжается напрямую, а в отчёте появляется
`прокси: … недоступен, работаю напрямую`. Строка `прокси:` печатается всегда.

Что это даёт по замерам: mastodon.social `000`→`200`, arctic-shift (reddit)
`422`→`200`, `api.tavily.com` `403`→`200`. Последнее означает, что ветка A без
прокси в этой сети вообще не работает.

Выключить: `--no-proxy` на один запуск или `DEEP_SEARCH_PROXY=` в окружении.
Сменить адрес: `DEEP_SEARCH_PROXY=http://host:port`. SOCKS5-порт `1081` того же
gost-контейнера не поддерживается — httpx нужен пакет `socksio`, а выходной IP у
обоих портов одинаковый.

**Движки SearXNG не проксируются.** Замер: `html.duckduckgo.com` отдаёт
challenge-страницу одинаково и напрямую, и через прокси (`202`, 0 результатов).
Капчу прокси не лечит, а google/brave через датацентровый IP ловят её быстрее.

**Страницы Crawl4AI не проксируются.** Проброс невозможен без правки исходников:
`proxy_config` в запросе отклоняется (`api.py` грузит любой body как
`Provenance.UNTRUSTED`), env контейнера Chromium игнорирует (Playwright ставит
свой `--proxy-server` шим), а серверный `crawler.base_config` живёт только в
`/app/config.yml` внутри образа — и его подмена вернула бы из дефолтов
`--allow-insecure-localhost` с `--ignore-certificate-errors`, то есть отключила бы
проверку TLS на каждом крауле. Практическое следствие: гео-блокированная страница
приходит ошибкой в ветке B, но её текст обычно приносит ветка A — Jina тянет
страницу со своей стороны. Ровно то, ради чего два источника и объединены.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `DEEP_SEARCH_PROXY` | прокси для внешних запросов, по умолчанию `http://127.0.0.1:8118`; пустое значение = напрямую |
| `TAVILY_API_KEY_1..3`, `JINA_API_KEY` | ветка `tavily+jina` (читает сам `custom-search`) |
| `CRAWL4AI_API_TOKEN` | ветка `searxng+crawl4ai`; фоллбэк — `<repo>/.env` |
| `INTERNET_CLAUDE_DIR` | путь к стеку, по умолчанию `~/internet-claude` |
| `SEARXNG_PORT`, `CRAWL4AI_PORT` | порты на localhost, по умолчанию `8880` / `11235` |
| `DEEP_SEARCH_SEARXNG_URL`, `DEEP_SEARCH_CRAWL4AI_URL` | полный override адресов |

## Безопасность

- значения ключей и токенов не печатать в чат и не подставлять в командную строку —
  скрипт читает их из окружения сам;
- URL из результатов поиска проходят `sanitize.partition_safe` (SSRF-вето на
  private/loopback/link-local) прежде чем попасть в Crawl4AI; отклонённый URL
  попадает в блок отказов с причиной.
